## Summary

Il Sistema Ripetizioni permette agli studenti di Nova di offrire e cercare aiuto accademico peer-to-peer.

**Approccio tecnico:**
- Nuova tabella `tutor_profiles` con relazione 1:1 a `profiles`
- Array `TEXT[]` per materie con GIN index per query performanti
- Integrazione con ProfileScreen/OtherProfileScreen esistenti
- Deep links HTTPS per WhatsApp/Instagram (fallback automatico)
- RLS policies per privacy (public read, owner write)

## Key Technical Decisions

### 1. Database Design

**Decision:** Tabella separata `tutor_profiles` invece di colonne in `profiles`

**Rationale:**
- Separazione concerns (non tutti gli studenti sono tutor)
- Relazione 1:1 esplicita con constraint UNIQUE
- Più facile da rimuovere/modificare in futuro
- Pattern già usato in Nova (es. `fcm_tokens`)

### 2. Subject Storage

**Decision:** `TEXT[]` array con GIN index

**Rationale:**
- Pattern esistente (`co_organizers UUID[]`)
- Query semplici con `.contains()`
- <1ms latency con GIN su 810 studenti
- Junction table overkill per questo scale

### 3. Deep Links

**Decision:** HTTPS URLs invece di custom schemes

**Rationale:**
- Fallback automatico a browser
- No configurazione Info.plist/AndroidManifest
- Più affidabile cross-platform

### 4. Profile Integration

**Decision:** `TutorProfileSection` widget separato

**Rationale:**
- Componente riutilizzabile (ProfileScreen + OtherProfileScreen)
- Segue pattern `ProfileStats`, `ProfileHeader`
- Loading state indipendente
